# Распределение ФУЛ между логистами

## Когда применять

- Пользователь приложил Excel-файлы (`.xlsx`, `.xls`) — обычно три: выгрузку ФУЛ из 1С,
  реестр Cloud и список сотрудников из 1С. Текста запроса может не быть совсем — это нормально,
  **ничего не уточняй, сразу запускай скрипт**.
- Пользователь просит распределить заказы / ФУЛ / упаковочные листы по логистам,
  найти повторные отправки или подготовить строки для Cloud.

Имена файлов, имена листов и порядок колонок могут быть любыми: скрипт сам определяет,
какой файл чем является, по заголовкам колонок.

## Как запустить

Одна команда. Передай **все** приложенные Excel-файлы (в любом порядке) или папку с ними,
и папку для результата:

```bash
python3 <папка навыка>/scripts/distribute.py <файл1> <файл2> <файл3> --out <папка результата>
```

- `<папка навыка>` — папка, где лежит этот SKILL.md.
- `<папка результата>` — папка, откуда пользователь может скачать файлы (папка выходных
  файлов сессии); если такой нет — `./result`.
- Нужен только Python 3 и `openpyxl` (для `.xls` — `xlrd`). Сеть не используется.

Скрипт создаёт:
- `distribution_result.xlsx` — результат для пользователя;
- `chat_message.txt` — готовый ответ для чата;
- `summary.json` — сводка в машинном виде.

Тот же ответ для чата скрипт печатает в stdout между служебными строками
`=== ОТВЕТ ДЛЯ ЧАТА ===` и `=== КОНЕЦ ОТВЕТА ===`.

## Как ответить пользователю

1. **Код выхода 0.** Ответ в чат = содержимое `chat_message.txt` **дословно**:
   не меняй ни слова, ни цифры, не переводи и не сокращай. Служебные строки
   `=== ... ===` и пути к файлам в ответ **не включай**. Приложи `distribution_result.xlsx`.
   Если скрипт напечатал строки `Предупреждение:`, добавь их одной строкой в конце.
2. **Код выхода 2** (ошибка входных данных). Перескажи пользователю текст после `ОШИБКА:`
   своими словами, кратко, и попроси приложить недостающий файл или исправить колонку.
   Не пытайся распределять заказы сам.
3. Если пользователь задаёт вопрос по результату («почему этот заказ отдан Петровой?»),
   отвечай **только** по листу «Журнал решений» в `distribution_result.xlsx` или по
   `summary.json` (поля `assignments[].reason` и `assignments[].candidates`). Цитируй обоснование,
   не придумывай своё и не обобщай: если один логист в отпуске, а другой уволен, так и скажи —
   не «все в отпуске».

## Чего не делать

- **Не выбирай группу и логиста сам** и не меняй решения скрипта — даже если кажется,
  что так «логичнее». Решения принимает скрипт по правилам заказчика.
- **Не подставляй значения** там, где скрипт написал «не определено».
- Не добавляй в ответ данные, которых нет в выводе скрипта.
- Не записывай ничего в 1С, Cloud или почту: результат — только файл.
- Письма логистам — черновики для человека: не отправляй их и не переписывай; если просят текст письма,
  бери его с листа «Письма логистам» или из `summary.json` (`letters[].body`).

## Что внутри результата

| Лист | Что там |
|---|---|
| Сводка | счётчики и какие файлы/листы/строки заголовков распознаны |
| Новые строки Cloud | ровно 12 колонок в порядке реестра Cloud — можно копировать в реестр |
| Повторные отправки | заказы, которые уже есть в Cloud или повторяются в пачке, и комментарий «Повторная отправка ФУЛа, ДД.ММ.ГГГГ» |
| Возможные пропуски | ФУЛ, которых нет в Cloud, хотя они старше последней записи реестра; с предложенными группой и логистом |
| Требует внимания | что нужно решить человеку: «Срочно» (строка не создана или логист не назначен) и «Проверить» |
| Письма логистам | черновик письма каждому назначенному логисту: его новые заказы, почему именно он, повторные ФУЛ по его заказам |
| Журнал решений | по строке на каждый ФУЛ: статус, группа, логист, правило и обоснование |
| Сотрудники | как агент понял список сотрудников: группа, доступность, загрузка |

## Правила (кратко)

Полностью — в `references/rules.md`, параметры — в `references/rules.json`.

1. Нет номера заказа → строка не создаётся. Заказ есть в Cloud → повторная отправка.
   Заказ повторяется в пачке → одна строка + комментарий о повторе. ФУЛ старше последней
   записи Cloud → возможный пропуск.
2. Группа: `air` → авиаперевозки; не `air` + Китай/Гонконг → ВЭД; не `air` + другая
   страна → мультимодальные. Нет данных → «не определено».
3. Логист: только сотрудники группы со статусом «Работает»; ассистенты и руководители
   не распределяют. Сначала — кто чаще вёл поставщика; если он недоступен или поставщик
   новый — наименее загруженный по заказам «в работе» (с учётом этой пачки).
   Один поставщик в пачке — один логист. Нет доступных → «не определено», в другую
   группу заказ не передаётся.
